يُعرِّف بروتوكول العميل-الوكيل واجهةً قياسيةً للتواصل بين وكلاء الذكاء الاصطناعي وتطبيقات العميل. المعمارية مُصمَّمة لتكون مرنة وقابلة للتوسع ومستقلة عن المنصة.

## فلسفة التصميم

تتبع معمارية البروتوكول عدة مبادئ رئيسية:

1. **متوافق مع MCP**: البروتوكول مبني على JSON-RPC، ويُعيد استخدام أنواع MCP حيثما أمكن حتى لا يحتاج المكاملون لبناء تمثيل آخر لأنواع البيانات الشائعة.
2. **UX أولاً**: مُصمَّم لحل تحديات تجربة المستخدم عند التفاعل مع وكلاء الذكاء الاصطناعي؛ مما يضمن وجود مرونة كافية لعرض نية الوكيل بوضوح، لكنه ليس أكثر تجريدًا مما يحتاج إليه.
3. **موثوق**: ACP يعمل عندما تستخدم محرِّر كود للتحدث مع نموذج تثق به. لا يزال لديك تحكم في استدعاءات أدوات الوكيل، لكن محرِّر الكود يمنح الوكيل الوصول إلى الملفات المحلية وخوادم MCP.

## الإعداد

عندما يحاول المستخدم الاتصال بوكيل، يقوم المحرِّر بتشغيل العملية الفرعية للوكيل عند الطلب، ويتم كل التواصل عبر stdin/stdout.

يمكن لكل اتصال دعم عدة جلسات متزامنة، لذا يمكنك إجراء خطوط تفكير متعددة في آنٍ واحد.

![إعداد الخادم-العميل](../../images/server-client.svg)

يستخدم ACP إشعارات JSON-RPC بشكل مكثف للسماح للوكيل ببث التحديثات إلى واجهة المستخدم في الوقت الفعلي. كما يستخدم طلبات JSON-RPC ثنائية الاتجاه للسماح للوكيل بتقديم طلبات لمحرِّر الكود: على سبيل المثال لطلب أذونات لاستدعاء أداة.

## MCP

في الغالب سيكون لمحرِّر الكود خوادم MCP مُكوَّنة من قِبَل المستخدم. عند إعادة توجيه المطالبة من المستخدم، يمرر الإعدادات الخاصة بها إلى الوكيل. هذا يسمح للوكيل بالاتصال مباشرة بخادم MCP.

![اتصال خادم MCP](../../images/mcp.svg)

قد يرغب محرِّر الكود نفسه في تصدير أدوات قائمة على MCP. بدلاً من محاولة تشغيل MCP وACP على نفس المقبس، يمكن لمحرِّر الكود توفير خادم MCP الخاص به كإعداد. بما أن الوكلاء قد يدعمون MCP فقط عبر stdio، يمكن لمحرِّر الكود توفير وكيل نقل صغير يُعيد توجيه الطلبات إليه:

![اتصال MCP بالنفس](../../images/mcp-proxy.svg)

## معمارية البروتوكول

```
محرِّر الكود                    وكيل ACP
     │                              │
     │──── initialize ─────────────>│
     │<─── initialized ─────────────│
     │                              │
     │──── sessions/new ───────────>│
     │<─── sessions/new (resp) ─────│
     │                              │
     │──── turns/new ──────────────>│
     │<─── turns/message (stream) ──│
     │<─── turns/complete ──────────│
```
